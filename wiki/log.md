## [2026-09-30] ingest | Reported: Spálená knihovna (C19, BurnCard x2) on an opponent holding 2 cards - only one burn ghost appeared in the opponent's hand strip. Game logic was fine (two BURNED callbacks, two queue entries). Cause in NewBattlefield: the ghost loop picked a random card-back rect right before each ghost and waited delay(220) between ghosts; in the same frame the hand-size effect (2 -> 0) removed both slots and their rects, so the second ghost found no rect and `continue` dropped it silently. With more cards in hand the second ghost could also land on the same back as the first. Fix: every pending loss gets a distinct slot and its rect captured up front, before the first delay (lossOrigins: queue index -> slot + rect, survives an effect restart when online CARD_LOST messages arrive one by one); the chosen slots go to lossSlotKeys and the shrink path removes those first, so the back that disappears is the one the ghost burned over, not another random one. lossSlotKeys is cleared when the hand grows (a redraw in the same state means the pending removal never comes).
